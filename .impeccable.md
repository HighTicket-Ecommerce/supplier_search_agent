## Design Context

### Users
SupplierHQ researchers enter product categories, narrow by supplier country/type and exclusions, then review supplier evidence. The user's November 10, 2026 clarification makes new supplier discovery the app's purpose: no retailer searches, list-comparison workflow or requirement to supply websites.

### Brand Personality
Clear, practical, calm. The interface should help a researcher start confidently without understanding crawlers, providers or execution limits.

### Aesthetic Direction
Keep the established Streamlit controls and restrained blue accent. Prioritize a compact, readable search form and one obvious Search action. Avoid new decorative UI or a separate design framework for this change.

### Design Principles
1. The default screen asks only for product types and business filters: supplier country, supplier type and exclusions.
2. Always discover websites from the product brief. Offer manufacturers, brand owners and optional distributors; remove retailer choices, website inputs and discovery toggles from the UI.
3. Keep target count, budget and explicit export consent under optional settings. The sidebar only loads saved research; comparison and directory tools remain API capabilities.
4. Preserve bounded backend defaults, explicit export consent and evidence checks.
5. Use labeled native controls, keyboard access and plain progress messages; retain technical diagnostics in collapsed details.
